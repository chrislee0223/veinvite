# 공통 보상 풀 정산 전환 — 실제 지급 연결 (비활성화된 준비 단계)

## 변경 내용
- `read_reward_shared_pool_mode_v1` / `commit_reward_shared_pool_v1`: 완료·시빌·최종 블록 증거를 확인한 신청자만 현 시점 **공통 온체인 잔액에서 실제 미지급액과 X 10 B3TR을 제외**하고 원자적으로 지급액을 확정한다.
- 과거의 미완료 초대 22명에 대해서는 미리 예약하지 않는다. 늦게 완료한 초대도 동일한 신원·시빌 검사를 통과한 뒤 동일한 공통 풀 지급 방식에 포함된다. 과거 완료·고정 지급금은 손대지 않는다.
- `read_reward_elastic_contingent_scope_liability_wei_v1`은 새 모드 활성화 때 잠정 라운드 예산을 더 이상 미지급 의무로 세지 않는다.
- `enforce_reward_queue_cohort_budget`, `validate_reward_x_promotion_split`은 **새 방식으로 산정한 건에만** 구형 라운드 한도를 건너뛰고, 기존 자금 원장·X 요건·신원·정산 트리거를 유지한다.
- 앱의 예약 Worker는 활성 모드에서 새 Writer를 우선 호출한다. 구형 소스 잔액 재분배 Worker는 활성 시 실행하지 않는다.
- 유저 문구·UI 디자인을 수정하지 않고 기존 `ELASTIC_SCENARIOS` 반환 수치만 공통 풀 기준으로 전환한다.

## 중요한 제약
- 새 정책은 **미완료자의 미래 보상을 사전 보장하지 않는다.** 현재 완료자에게 공통 풀 상당액을 지급하면 이후 완료자는 새 자금이 들어올 때까지 대기할 수 있다. 이 정책은 기존 사용자 요구에 따른 것이며 '모든 미래 사용자 즉시 지급 보장'과 동시에 성립하지 않는다.
- 유저에게 유효한 X 보상 10개는 **이미 확정된 것만** 별도 차감하고, 새로운 보상 확정 시 사용자 수 × 10을 실제 예산에서 확보한다.
- 80/20은 온체인 보상 풀에서 이미 분리되므로 **추가 운영비 20%를 공제하지 않는다.**
- 계정·지급 원장·지급 기록을 삭제하거나 변경하지 않는다. 소스 보호금 숫자를 단순히 0으로 고치지 않고, 신규 가격의 기준에서 제거한다.

## Deployment Gate
1. DB migration은 **enabled=false**. 적용만으로 기존 금액·송금·Claim 기능은 바뀌지 않는다.
2. Production과 동일한 스키마에서 새 writer/트리거의 자금 부족, 동시 실행, 시빌 차단, X 생성 및 과거 완료 테스트 필수.
3. 코드 CI (타입 검사, 테스트, 보안, 브라우저 QA, 빌드) 통과 후 API/worker 먼저 배포.
4. 활성화 시 현재 미지급·급증 후보·기존 원장을 검증하고 DB transaction에서 `shared_pool_settings.enabled=true` 설정. 별도 외부 크론/기존 보상 루트 차단 확인.
5. 최종 활성화 후 실시간 조회 수치와 한 번의 정상 미션 완료 → Claim → 송금 → X 검증까지 확인한다. **이 문서를 작성한 시점에서는 2~5번이 끝나지 않았다.**
