# VeInvite 이용 분석 운영 기준

## 목적

이용 분석은 VeInvite의 실제 방문·재방문·체류시간·화면 사용 패턴을 이해하고 UI/UX, 홍보, 운영 효율을 개선하기 위한 **운영용 통계**입니다.

이 데이터는 추천 관계, 신규/복귀 자격, Sybil 판정, 미션 완료, 예상 보상, 실제 보상 준비·지급에 절대 사용하지 않습니다.

## 기본 지표

- **일일 순방문자(UV)**: 서울 시간 기준 같은 일일 익명 브라우저 ID가 하루에 여러 번 들어와도 1명으로 집계합니다. 날짜가 바뀌면 새 익명 ID를 사용합니다.
- **방문 세션 수**: 한 브라우저 탭의 방문 단위입니다. 새 탭/다시 열기, 서울 기준 날짜 변경 또는 30분 이상 비활성 뒤 다시 사용하면 새 세션이 될 수 있습니다.
- **신규 방문자**: 해당 브라우저에 VeInvite 과거 방문 표시가 없었던 방문자입니다.
- **재방문자**: 브라우저에 이전 VeInvite 방문 여부가 남아 있는 방문자입니다. 서버는 전날의 익명 ID와 오늘의 익명 ID를 연결하지 않습니다.
- **방문자당 세션 수**: 세션 수 ÷ 일일 순방문자 수입니다.
- **활성 이용시간**: VeInvite가 화면에 보이고 브라우저 포커스가 있을 때만 30초 단위 heartbeat로 누적합니다. 백그라운드 탭 시간은 제외합니다.
- **평균/중앙 이용시간**: 세션별 활성 이용시간의 평균과 중앙값입니다.
- **화면 조회**: home, guide, leaderboard, settings, invite_landing, privacy, terms 등 정해진 화면 이름만 기록합니다.
- **언어**: VeInvite에서 선택된 지원 언어 코드만 기록합니다.
- **기기 구분**: mobile/tablet/desktop의 넓은 범주만 기록합니다.
- **유입경로**: direct/x/telegram/search/vechain/other의 범주만 기록합니다.
- **지갑 연결 사용자**: 검증된 VeInvite 지갑 세션이 있었는지 boolean 값만 기록합니다. 이용 분석 DB에는 지갑 주소를 저장하지 않습니다.

## 개인정보 최소화

이용 분석 저장소에는 다음 값을 저장하지 않습니다.

- 원본 IP 주소
- 전체 User-Agent 문자열
- 지갑 주소 또는 지갑 주소 해시
- 초대 코드
- URL query string
- 전체 referrer URL

브라우저에는 서울 시간 기준 **하루 동안만 재사용되는 무작위 익명 ID**를 저장합니다. 날짜가 바뀌면 새 ID를 만들며, 서버에는 그 ID의 SHA-256 digest만 저장합니다. 장기 재방문 판별을 위해 이전 ID를 보존하거나 날짜 사이에서 서로 연결하지 않습니다.

브라우저에는 `이전에 VeInvite를 방문한 적이 있음/없음`이라는 최소 표시만 남겨 재방문 통계에 사용합니다. 사용자가 개인정보처리방침 페이지에서 익명 이용 통계를 끄면 일일 익명 ID, 과거 방문 표시, 분석 세션 저장값을 제거하고 이후 분석 이벤트 전송을 중단합니다.

원본 IP와 User-Agent는 이용 분석 DB에 저장하지 않습니다. 요청 남용 방지와 봇 제외를 위해 요청 처리 중 기술 정보가 짧게 사용될 수 있으며, rate-limit 저장소에는 기존 VeInvite 보안 정책에 따라 해시된 subject만 남습니다.

## 원본 데이터 보관 및 장기 통계

- 원본 익명 방문자/세션 데이터는 **최대 30일**만 유지합니다.
- 매일 기존 Vercel 운영 cron의 housekeeping 단계가 30일을 초과한 세션을 확인합니다.
- 삭제 전 날짜별 핵심 지표와 locale/device/source 분류 통계를 식별자 없는 일일 집계값으로 확정합니다.
- 확정 후 해당 날짜의 원본 세션과 더 이상 참조되지 않는 일일 visitor hash를 삭제합니다.
- 장기 조회는 최근 30일 원본 집계와 과거 일일 rollup을 합쳐 반환하므로 과거 통계는 유지됩니다.

## 집계 제외

- Vercel Preview 및 로컬/개발 환경
- `/admin` 운영자 화면
- `/ui-test` QA 화면
- 알려진 crawler/bot User-Agent
- 운영자가 지정한 관리자 지갑

관리자 지갑 목록은 이용 분석 정책용 설정으로 별도 관리합니다. 해당 목록은 **운영 통계에서만 제외하기 위한 기준**이며, 추천 관계, 신규/복귀 자격, Sybil 판정, 미션, 보상, 원본 초대 기록, 감사 로그를 변경하거나 삭제하지 않습니다.

방문자는 처음에는 지갑을 모르는 일일 익명 ID로 기록됩니다. 제외 대상 관리자 지갑이 인증되면 서버는 인증된 지갑을 관리자 목록과 그 순간에만 대조하고, 해당 **서울 시간 기준 당일 익명 방문 ID**를 이후 이용 통계에서 제외 표시합니다. 방문 분석 테이블에는 지갑 주소나 지갑 주소 해시를 기록하지 않습니다.

관리자 제외가 확정되어도 해당 익명 원본 세션은 정상 보존 기간까지 유지하며, 조회·일일 rollup에서는 제외합니다. 같은 날 관리자 인증 전에 발생한 화면 조회도 배포 이후 생성되는 짧은 세션별 화면 카운터를 이용해 집계에서 차감합니다. 이 보조 데이터는 원본 세션과 함께 삭제됩니다.

**중요:** 이 기능이 배포되기 전에 이미 수집된 익명 방문 기록에는 지갑을 역추적할 수 있는 정보가 애초에 없으므로, 과거 익명 방문을 관리자 지갑과 소급 연결해 제거하지 않습니다. 이는 개인정보 최소화 설계를 유지하기 위한 의도된 제한입니다. 반면 지갑 주소가 원래 존재하는 인증·초대·미션·운영 리더보드 통계에서는 기존 관리자 활동도 제외할 수 있습니다.

운영자와 QA 트래픽이 실제 사용자 지표를 부풀리지 않도록 하되, 원본/감사 데이터의 역사적 사실은 보존합니다.

## 초대 링크 보호

`/i/[code]` 방문은 `invite_landing`이라는 고정 화면 이름으로만 기록합니다. 실제 초대 코드, path 전체값, query string은 이용 분석 이벤트에 전달하거나 저장하지 않습니다.

## 사용자 제어

개인정보처리방침(`/privacy`) 하단에서 익명 이용 통계를 ON/OFF 할 수 있습니다.

- 기본값은 ON입니다.
- OFF로 바꾸면 이후 이용 분석 전송을 즉시 중단합니다.
- OFF 상태는 브라우저에 저장됩니다.
- OFF로 바꿔도 지갑 연결, 초대, 미션, 보상, 언어 설정 등 VeInvite의 다른 기능에는 영향이 없습니다.

## 운영자 조회

운영자 전용 API:

`GET /api/admin/usage-analytics?days=30`

- 기본 30일, 최대 3,650일
- 기존 VeInvite 운영 지갑 인증 필요
- 서울 시간 기준 일별 지표 반환
- locale/device/source/view breakdown 제공
- read-only이며 reward write를 수행하지 않음
- 관리자 지갑으로 확인된 당일 익명 방문은 자동 제외

따라서 사용자가 ChatGPT에 `오늘 방문자 알려줘`, `이번 주 재방문율과 체류시간 알려줘`, `어떤 언어 사용자가 많아?`처럼 요청하면 운영자 인증 데이터로 요약할 수 있습니다.

## 해석할 때 주의할 점

- 순방문자는 법적·물리적 '사람 수'가 아니라 **일일 익명 브라우저 기준 추정치**입니다.
- 같은 사람이 여러 기기/브라우저를 쓰면 하루에도 여러 방문자로 잡힐 수 있습니다.
- 브라우저 저장소를 지우거나 이용 통계를 껐다 다시 켜면 이후 신규 방문자로 보일 수 있습니다.
- 반대로 같은 브라우저 프로필을 여러 사람이 공유하면 1명으로 잡힐 수 있습니다.
- 날짜별 익명 ID를 서로 연결하지 않기 때문에 여러 날짜 범위의 `unique_visitors`를 실제 고유 인원 수로 해석하면 안 됩니다. 일별 UV와 방문 추세를 중심으로 봅니다.
- 데이터 수집은 기능 배포 이후부터 시작하므로 과거 방문량을 소급 복원하지 않습니다.
- 관리자 지갑 제외도 배포 이전의 익명 방문 기록을 소급 식별하지 않습니다.
