# VeInvite 관리자 화면 정리 및 보존 기준 (2026-10-18)

## 원칙
- 운영자 전용 네 페이지는 로그인·on-chain 운영자 권한 검사 후 제공되며, 일반 사용자의 앱 내 메뉴에 노출하지 않습니다.
- 이미 사용 중인 보상·시빌 복구 API 및 cron/정산 로직은 화면의 존재 여부와 무관하게 별도 안전성/의존성 검사를 거친 뒤에만 제거할 수 있습니다.
- 수동 운영자 확인이 필요한 작업을 자동 CLEAR/BLOCK 또는 자동 보상 무효화로 대체하지 않습니다.

## 보존할 관리자 페이지 (현재 4개)
1. `/admin/sybil-review` — Sybil HOLD 수동 심사, 초대자·피초대자 제한 해제, 오탐 복구, 사용자 이의신청 처리. 2026-08-29부터 구축. **유지**.
2. `/admin/rewards` — 보상 준비·서명·최종성 확인·지급 이력 및 복구 수단. 2026-08-27부터 구축. **유지**.
3. `/admin/participants` — 운영자용 참가자 상태·집계 보기. 2026-08-27부터 구축. **유지(읽기 전용)**.
4. `/admin/funding` — VeBetterDAO 자금 배분 및 설정 변경. 2026-08-27부터 구축. **유지(트랜잭션 서명 권한 분리)**.

## 추가된 지급 후 연결 지갑 재심사
- 2026-10-17 도입한 `PaidSiblingRechecks`는 새로운 독립 관리자 페이지가 아니라 기존 `/admin/sybil-review` 내 추가 섹션입니다.
- 이전에는 `이미 지급된 CLEAR + 같은 초대자/브라우저 + 나중에 차단된 지갑`만으로 수동 재심사를 띄웠습니다. 이는 정상적인 최초 참여와 이후 중복 참여를 혼동할 수 있습니다.
- 이제는 **최초 지급받았던 피초대자에 대해 기존 CLEAR 시점 이후 새롭게 수집된 HIGH 독립 증거(HISTORICAL_CONSOLIDATION, HISTORICAL_REWARD, CLUSTER_LINK, MISSION_BEHAVIOR)** 가 있을 때에만 특수 재심사 대상을 노출합니다.
- 동일 브라우저 연관성이나 후발 지갑의 시빌 증거만으로는 최초 CLEAR를 재판정하지 않으며, 해당 연결은 이미 존재하는 제한·보안 관찰·증거 테이블에서 계속 추적할 수 있습니다.
- 이전 CLEAR 재심사 종결 이후 같은 옛 증거를 다시 사용하지 않습니다. 수동 BLACKLIST가 실제 필요한 경우 기존 불변 지급 영수증을 수정하지 않고 감사 가능한 과거 추천 무효화/상계 처리 경로를 사용합니다.
- 별도 페이지/API/DB 테이블을 무작정 삭제하지 않습니다. 증거가 없을 때 특수 재심사 섹션을 **화면에서 숨기되**, 새 HIGH 독립 증거가 등장하는 예외적인 경우에는 운영자가 수동 처리할 수 있도록 유지합니다.

## 검증 요건
- 기존 CLEAR/BLACK/PAID 및 상계 미변경
- 인증된 운영자만 읽기/쓰기 가능, RLS 및 비인증 접근 불변
- 지급/긴급중지/오탐 복구/이의신청 흐름 기존 회귀 테스트 통과
- SQL view 단계에서 낮은 신뢰도 신호를 걸러 API 및 보상 원장의 기준이 뒤바뀌지 않도록 보장
- 추가 UI는 실질적인 후보가 없으면 표시하지 않음

### 알려진 경계
동일 기존 restriction에 대해 운영자가 CLEAR를 이미 확정한 후에 독립적인 새 증거가 발견된 경우에는 별도의 기존 시빌 사건 심사/이의신청 및 과거 추천 무효화 경로를 이용해야 합니다. 현 특수 재심사는 (network, paid_invite_code, restriction_id) 별로 판정 1건을 기록하며 이를 자동 덮어쓰지 않습니다.
