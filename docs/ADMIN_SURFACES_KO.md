# VeInvite 관리자 화면 보존 및 중복 기능 정리 (2026-10-18)

## 운영 원칙
- 기존 운영자 전용 관리자 화면 4개는 온체인 운영자 권한 및 지갑 세션을 검증하며, 일반 앱 메뉴에는 노출하지 않습니다.
- 시빌 CLEAR 이후의 후속 증거 수집, 시빌 HOLD/BLACK 판정, 오차단 복구, 사용자 이의신청, 과거 부정 추천 무효화 및 보상 상계는 기존 경로를 사용합니다.
- 후속 시빌 증거가 나타났다는 이유만으로 이미 지급된 보상이나 과거 CLEAR 판정을 자동 변경하지 않습니다.
- 관리자 API 및 자동 지급/감시 기능은 화면 삭제 여부와 독립적으로 보존합니다.

## 유지하는 관리자 페이지
1. `/admin/sybil-review`: 기존 HOLD 수동 검토, 차단·해제, 이의신청, 지급 후 시빌 사건 처리
2. `/admin/rewards`: 보상 준비·서명·내역 확인 및 장애 복구
3. `/admin/participants`: 참가자·운영 집계
4. `/admin/funding`: 자금 관리 및 승인 작업

## 2026-10-18 변경: 전용 지급 후 연결 지갑 재심사 기능 폐기
- 2026-10-17 추가한 전용 사후 재심사 컴포넌트 및 엔드포인트는 기존 시빌 후속 감시·수동 검토와 중복되어 삭제합니다.
- 전용 데이터베이스 뷰, RPC, 판정 테이블은 새 코드의 운영 배포가 **READY**인 것을 확인한 뒤 별도 정리 마이그레이션으로 `RESTRICT`를 사용해 제거했습니다. 2026-10-18 운영 DB에서 세 객체 모두 제거된 상태를 확인했습니다.
- 기존 마이그레이션 SQL과 적용 이력은 재현성 및 감사 기록 유지를 위해 보존합니다. 기존의 시빌 감시 테이블, 과거 추천 무효화/상계 기록, 보상 영수증은 삭제하지 않습니다.
- 삭제 당시 전용 판정 테이블은 **0건**, 전용 대기 목록도 **0건**이었고, 다른 DB 뷰나 함수에서 해당 객체를 참조하지 않았습니다.

## 검증 기준
- 운영자 로그인/권한 경계와 기존 수동 검토 UI가 동일하게 동작
- 기존 Sybil 자동 검증, CLEAR 후 증거 감시, HOLD/BLOCK 및 오차단 복구 정상
- 기존 지급·리더보드·과거 추천 무효화·상계 불변
- DB 정리 전 코드 운영 배포 성공, 데이터베이스 전용 객체 제거 및 새 마이그레이션 이력 검사 통과
