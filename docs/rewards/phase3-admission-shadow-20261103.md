## 새 계산기: rewardAdmissionShadow.ts

이 계산기는 사용 가능한 코호트 예산과 **현재 물리적 유동성**의 작은 쪽을 사용합니다.

1. **같은 금액을 두 번 빼지 않는다.** 이미 PAID 된 평생 누적 약정액은 코호트 예산에서만 차감; 물리적 풀에는 **미지급 고정 부채와 아직 살아 있는 보호액**만 차감.
2. 현재 코호트 미지급 보장, 과거 코호트 보호, X프로모션/기타 보류, 안전 유보액은 **겹치지 않도록 정규화**한 후 계산한다.
3. DAO 수령 증빙·물리적 풀 관측·부채 장부 정합성이 확인되지 않으면 fail closed.
4. 풀 관측이 5분 이상 오래되거나 오히려 미래 값이면 fail closed.
5. 미해결 구 코호트 보장 부족 위험이 있으면 보장형 신규 참여를 승인하지 않는다.
6. 동시 요청 두 개가 동일 스냅샷으로 통과하는 경쟁 상태를 확인했다. **이 프리뷰는 승인 수단이 아니다.** 실제 최소 보장에는 다음 DB 원자적 작업이 필수.
7. 본 계산기는 기존 사용자/초대 등록/Claim에 연결하지 않으며 반환값 `authorizesAdmission: false`로 고정.

## 향후 실제 RPC 구현 전에 필요한 조건

- 초대 적격성 검증과 해당 라운드 자금 영수증 확인 후 DB 거래에서 코호트 자금 행 및 동일 초대의 보장 내역을 잠근다.
- `invite_code + policy_version` 등 고유 키로 **중복 요청을 멱등 처리**한다. 한정된 슬롯을 중복 계산하지 않는다.
- 지급 확정/취소와 최소 보장 해제, 라운드 종료 경계를 하나의 부채 장부 기준으로 검증한다.
- 100~1,000 동시 요청, 공격자의 미션 미완료 잠금, 늦은 DAO 청구, Sybil 유예/번복, 체인 최종성, Claim 재시도 및 크론 중복 실행 통합 테스트가 필수.
- 기존 라운드에 신규 보장이나 완료 기한을 **소급 적용하지 않는다**. 새 기능을 실제로 활성화하려면 사용자 공지와 정책 버전 경계가 필요.
- 해당 라운드 수령 대상 인원이 확정되기 전에는 코호트 전체를 첫 성공자에게 지급하지 않는다.
- 신규 보상 지급 상승 자체는 **아직 구현/활성화하지 않았다**.
