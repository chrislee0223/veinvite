# Known Limitations — 2026-09-07

- The full automatic reward pipeline is enabled on mainnet and passes readiness checks, but the first genuine end-to-end automatic B3TR payout has not happened yet because no production referral has completed every eligibility requirement. Do not fabricate a referral just to test payout.
- VeInvite performs an immediate best-effort reward iteration when an active invite page verifies a completed eligible referral. The independent Vercel fallback cron currently runs daily because the project is on the Hobby plan. A browser that closes before reconciliation can therefore rely on the next scheduled recovery run rather than an hourly worker. A higher-frequency independent recovery worker is a future infrastructure upgrade.
- The Production Supabase organization was observed on the Free plan on 2026-09-07. Current Supabase backup documentation guarantees scheduled daily backups for paid plans and recommends regular logical dumps plus off-site storage for Free projects. VeInvite therefore must not assume a platform restore point exists. `docs/DISASTER_RECOVERY_KO.md` and the fail-closed backup/restore-drill helpers document the current manual recovery path. Recheck plan/backup capabilities whenever billing or infrastructure changes.
- Observation-only Sybil infrastructure is now present for on-chain funding relationships, behavior fingerprints and post-payout B3TR recipient flow. However, Production `sybil_onchain_snapshots`, `sybil_review_events`, and B3TR recipient-flow snapshots still have no real populated evidence as of this review. Do not describe the deeper automated Sybil observation pipeline as fully proven until the feature gate, cron execution and real observations are verified together.
- Behavior similarity currently remains observation-only. Matching popular dApp sequences alone intentionally carries no suspicion score; stronger correlation requires independent timing/funding/cohort evidence. Automatic blocking from these observation signals is not enabled.
- Post-payout B3TR recipient-flow observation is implemented, but there has been no genuine Production payout yet, so the 24-hour recipient-flow path has not been validated against real payout data. Known protocol destinations are exempted; exchange/custody allowlisting should be expanded only from verified real evidence rather than guessed address lists.
- The dedicated Reward Distributor uses a server-side signing secret. It is separated from the app-admin wallet and holds VTHO for gas only, but long-term signer hardening should move signing material to a managed signing/HSM-style service if the project reaches materially higher reward volume.
- The current operator monitoring runs inside the reconciliation cron. If that cron itself stops completely, it cannot report its own absence. An independent heartbeat/watchdog is still required for mature operations.
- The current CI strongly validates migrations, disaster-recovery safeguards, user-facing copy, forecast behavior, server invariants, TypeScript, reward-accounting regressions, dependency security, and production builds. It does not yet run real-browser Playwright tests across phone viewport sizes. Browser-level accessibility and visual-regression coverage are recommended as a later QA upgrade.
- Privacy and Terms are published in all supported app languages, but final jurisdiction-specific legal review remains an external launch/scale item. Translation checks can improve natural wording but are not a substitute for native legal review.
- Device fingerprinting is not implemented. Any future device-level abuse signal should be optional, privacy-minimizing, disclosed appropriately, and only one signal among several rather than an automatic block.
