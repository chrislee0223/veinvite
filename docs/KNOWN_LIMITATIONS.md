# Known Limitations — 2026-09-01

- The full automatic reward pipeline is enabled on mainnet and passes readiness checks, but the first genuine end-to-end automatic B3TR payout has not happened yet because no production referral has completed every eligibility requirement. Do not fabricate a referral just to test payout.
- VeInvite performs an immediate best-effort reward iteration when an active invite page verifies a completed eligible referral. The independent Vercel fallback cron currently runs daily because the project is on the Hobby plan. A browser that closes before reconciliation can therefore rely on the next scheduled recovery run rather than an hourly worker. A higher-frequency independent recovery worker is a future infrastructure upgrade.
- Historical on-chain Sybil analytics currently observe wallet age and initial VET/VTHO funding relationships. They are deliberately observation-only to avoid blocking legitimate users from weak correlation signals. The newly added recipient forensic view also reports how many paid referrals have or have not received this deeper historical scan.
- General B3TR wallet-to-wallet transfers are not indexed. Detecting many invitee wallets later consolidating B3TR into one common wallet requires a separate Transfer-event indexer and correlation report.
- The dedicated Reward Distributor uses a server-side signing secret. It is separated from the app-admin wallet and holds VTHO for gas only, but long-term signer hardening should move signing material to a managed signing/HSM-style service if the project reaches materially higher reward volume.
- The current CI strongly validates migrations, user-facing copy, forecast behavior, server invariants, TypeScript, reward-accounting regressions, dependency security, and production builds. It does not yet run real-browser Playwright tests across phone viewport sizes. Browser-level accessibility and visual-regression coverage are recommended as the next QA upgrade.
- Privacy and Terms are published in all supported app languages, but final jurisdiction-specific legal review remains an external launch/scale item. Translation checks can improve natural wording but are not a substitute for native legal review.
- Device fingerprinting is not implemented. Any future device-level abuse signal should be optional, privacy-minimizing, disclosed appropriately, and only one signal among several rather than an automatic block.
